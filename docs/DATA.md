# Data dictionary

Everything this repo collects, where it comes from, how to regenerate it, and what each field means.
There are two kinds of data, kept apart on purpose:

| | **Usage data** — what players do | **Reference data** — what the rules are |
|---|---|---|
| Question it answers | "What does a typical Garchomp run?" | "What does Earthquake do? Can Garchomp learn it?" |
| Lives in | `sources/snapshots/*.json`, `sources/icons/` | `src/champions/data/*.json` |
| Produced by | `champions sources <name>` (`src/champions/sources/`) | `champions fetch <name>` (`src/champions/fetch/`) |
| Origin | Community stat sites (scraped HTML) | PokeAPI + Pokémon Showdown source files |
| Changes | Constantly (meta shifts) | Rarely (new regulation / patch) |

Join key between the two: usage snapshots are keyed by `common.key(name)` (lowercase, letters and digits
only: `Mr. Rime` → `mrrime`, `Garchomp-Mega-Z` → `garchompmegaz`). Reference data uses Showdown ids for
moves/items/abilities (also lowercase alphanumeric) and PokeAPI-style hyphenated names for Pokémon forms
(`garchomp-mega-z`).

All files carry a `fetched_at` (UTC ISO timestamp) except where noted. Check it, and each usage entry's
`as_of`, before trusting a number.

## Part 1 — Usage data (`sources/snapshots/`)

One file per source and format: `<source>-<format>.json`. Raw pages are cached in `sources/cache/`
(gitignored) so reruns resume and parsers can be fixed without re-downloading. Judgement on how far to
trust each source is in `sources/README.md`; this section only describes the shape. Entry counts change
with every full fetch, so none are listed here: count `pokemon` in the file.

### Common snapshot shape

```json
{ "source": "munchstats", "format": "doubles", "url": "<template>", "notes": "...",
  "fetched_at": "2026-11-11T00:36:58+00:00", "pokemon": { "<key>": { ...entry... } } }
```

### Entry fields

Every field is optional; a source fills what it publishes. **Percentages are 0–100** unless noted.
Dict fields are `{display name: percent}`; spreads are keyed by Stat Points `"hp/atk/def/spa/spd/spe"`.

| field | type | meaning |
|---|---|---|
| `name` | str | Display name as the source writes it (OP.GG: lowercase slug) |
| `rank` | int | Usage rank, 1 = most used |
| `usage` | float | Usage % (see per-source caveats: rounded, modelled, or absent) |
| `winrate` | float | Win % |
| `as_of` | str | When the *source* says its data is from (free-form text; not our fetch time) |
| `moves` | `{move: pct}` | Move usage |
| `items` | `{item: pct}` | Held-item usage |
| `abilities` | `{ability: pct}` | Ability usage |
| `natures` | `{nature: pct}` | Nature usage |
| `spreads` | `{"hp/atk/def/spa/spd/spe": pct}` | Stat Point spreads; each total is ≤ 66, max 32 per stat |
| `teammates` | `{name: pct}` | Teammate co-occurrence % (Pikalytics) |
| `teammate_ranks` | `[name, ...]` | Teammates ordered by rank only, no % (MunchStats) |
| `slug` | str | OP.GG URL slug |

### Per source

| file | format | fields filled | structural notes |
|---|---|---|---|
| `munchstats-doubles.json` | Doubles | name, rank, as_of, moves, items, abilities, natures, spreads, teammate_ranks | Screen-reads of the game's own Battle Data. No `usage`/`winrate`: the game publishes rank only. Moves cover the top 10 only. |
| `pikalytics-doubles.json` | Doubles | name, rank, usage, winrate, moves, items, abilities, teammates | Tournament teams (Limitless), Reg M-C. `usage` rounded to whole %. Move % use a different scale than MunchStats. No natures or spreads |
| `opgg-singles.json` | **Singles** | name, slug, as_of, moves, spreads | Ladder data. Singles only (Doubles tab is client-side). Move lists partial. No usage/rank |
| `championslab-doubles.json` | Doubles | name, rank, usage, winrate, as_of | Top 20 only. Extra top-level key `teams`: 8 winning tournament teams, each `{player, event, wins, losses, players, team: [6 names]}` |

Pokémon Zone and pokebase.app are not collected; see `sources/README.md` for why and for how far to trust each source.

### `sources/comparison.md`

Generated by `champions sources compare`: side-by-side agreement tables across the sources. Regenerate
after any new fetch; the conclusions in `sources/README.md` were drawn from a 30-Pokémon sample.

### `sources/icons/`

PNG sprites, one per roster form, named by form (`garchomp-mega-z.png`), used to recognise Pokémon in
screenshots. `index.json`:

- `icons`: `{form: {"source": <url>, "bytes": n}}`
- `misses`: forms with no sprite available (Pikachu cosplay/cap forms, some regional/cosmetic variants).
  Reported rather than guessed.

Source: Pikalytics' 128 px Champions sprites; Champions Lab 512 px art as fallback for default forms.

### `usage.py` (a reader, not a source)

`defaults(name, dex)` turns the MunchStats snapshot into likely battle-spec fields (top moves, item,
ability, nature, SP) for pre-filling an opponent. They are each the *most common* value independently, not
the most likely combination.

## Part 2 — Reference data (`src/champions/data/`)

Refresh with `champions fetch champions` first, then `moves` and `reference` (both read `champions.json`).
`champions check-roster` cross-checks the roster against Showdown and exits 1 on a mismatch.

### `champions.json` — roster

Source: PokeAPI `pokedex/champions` (`fetch/champions.py`). Top level: `fetched_at`, `source`,
`species_count` (231), `pokemon` (380 forms).

| field | type | meaning |
|---|---|---|
| `name` | str | Form name, PokeAPI style (`garchomp-mega-z`, `pikachu-belle`). Primary key |
| `species` | str | Base species name (`garchomp`) |
| `dex_id` | int | National Dex number |
| `is_default` | bool | True for the species' default form (231 of 380) |
| `is_mega` | bool | Mega form (82) |
| `new_in_mc` | bool | Added in Regulation M-C (35). **Hand-maintained** list `NEW_IN_MC` in `fetch/champions.py`; PokeAPI has no regulation info. Verified by `check-roster` |
| `types` | `[str]` | One or two lowercase types |
| `stats` | `{stat: int}` | Base stats: `hp, attack, defense, special-attack, special-defense, speed` |
| `abilities` | `[str]` | Ability slugs the form can have |
| `hidden_ability` | str \| null | Which of those is the hidden one |

Gigantamax forms are excluded.

### `moves.json` — moves

Source: Showdown's compiled main-series `moves.json`, with the `champions` mod's `moves.ts` overrides merged
on top, plus PP from Serebii (`fetch/moves.py`). Short descriptions from Showdown `data/text/moves.ts`.
Top level: `fetched_at`, `source`, `learnsets_source_commit` (`{sha, date}` of the Showdown commit),
`moves` (510, keyed by Showdown id). Only moves some Champions form can learn are included.

| field | type | meaning |
|---|---|---|
| `name` | str | Display name |
| `type` | str | `Ground`, `Fire`, ... |
| `category` | str | `Physical`, `Special`, `Status` |
| `base_power` | int | 0 for status moves. Already includes Champions overrides |
| `accuracy` | int \| true | `true` = never misses. Already includes overrides |
| `pp` | int \| null | From Serebii's Champions table (not Showdown). null if not listed |
| `priority` | int | Move priority bracket |
| `target` | str | Showdown target (`normal`, `allAdjacent`, `allAdjacentFoes`, `self`, `allySide`, ...) |
| `flags` | `[str]` | Showdown flags, sorted (`contact`, `protect`, `punch`, `sound`, ...) |
| `multihit` | int \| `[min, max]` \| null | Fixed hit count (`2`), random range (`[2, 5]`), or null (14 moves have it) |
| `short_desc` | str | One-line effect text for the base games |
| `champions_overrides` | object \| null | Fields Champions changes versus the main games (31 moves), e.g. `{"basePower": 90}`. Keys use Showdown names. null if unchanged |

Caveat: `short_desc` is base-game text; for the 31 overridden moves it may not mention the Champions change.

### `learnsets.json` — who can learn what

Same top-level metadata as `moves.json`, then `learnsets`: `{form name: [move ids]}` for all 380 forms,
sorted. Source: Showdown `data/mods/champions/learnsets.ts`. Forms Showdown doesn't list separately (Megas,
cosmetic forms) fall back to their base species; Floette is mapped to `floetteeternal`.

### `items.json` — held items

`items`: `{id: {name, short_desc}}`, 165 entries. Only items that are *legal in Champions* are kept
(165 of Showdown's 585): an item is excluded if flagged `isNonstandard` in Showdown's `items.ts` unless the
champions mod overrides that flag to null (that is how Mega Stones are included). Names come from
Showdown's compiled `items.js`, descriptions from `data/text/items.ts`.

### `abilities.json` — abilities

`abilities`: `{slug: {name, short_desc, champions_override}}`, 216 entries (every ability any roster form
has). Names and descriptions come from PokeAPI (`short_effect`, falling back to the latest flavor text).
`champions_override` is true (7 abilities) when the Showdown champions mod changes the ability's behavior,
in which case the PokeAPI description may be out of date for Champions.

### `types.json` — type chart

`chart`: `{Attacker: {Defender: multiplier}}` over the 18 types; multipliers are `0`, `0.5`, `1`, `2`.
Read as "a `Bug` move hitting a `Dark` Pokémon does `chart["Bug"]["Dark"]` = 2×". Stellar is excluded
(Tera-only).

## Known gaps

- No `rules.json` yet (level fixed at 50, Stat Point budget, etc.). `main` has one; it was not brought over.
- Reference data is not shipped as package data: `pyproject.toml` does not list `data/*.json`.
- `short_desc` for Champions-overridden moves/abilities may describe the base-game behavior.
- Usage sources disagree on measure and scale; see `sources/README.md` before combining them.
